# 02｜同一套模型换一个数据集：KuaiRec 的协议与结果

上一篇把 KuaiRec 的标签定死了：`watch_ratio >= 1.0`，按首次播放判定。这一篇把同一套 Popularity / MF / Two-Tower / SASRec 放上去跑一遍，回答一个看起来简单、实际很容易答错的问题：

**同一套代码换一份数据，指标从 0.096 掉到 0.019，是模型变差了吗？**

不是。这一篇要把"为什么不是"拆成可核对的量。

（顺带一提：这个"掉 5 倍"不是所有模型都有的现象。同一份数据上 SASRec 从 0.193 变成 0.250——反而更高。**掉多少取决于模型能用上多少历史**，这本身也是一条线索。）

## 一、除了数据和标签，什么都没换

| | MovieLens-1M | KuaiRec |
|---|---:|---:|
| 正反馈规则 | 评分 >= 4 | `watch_ratio >= 1.0`（首次播放） |
| 用户 / 物品 | 6,038 / 3,533 | 7,176 / 10,669 |
| 正样本交互 | 575,281 | 3,557,727 |
| 训练交互 | 569,231 | 3,543,377 |
| 评测用户 | 3,025 | 7,175 |
| 物品无训练交互 | 6 | 43 |
| 验证/测试同秒用户 | 0 | 0 |

模型侧完全复用：`rank_items_by_popularity`、`MatrixFactorization`、`TwoTowerModel`、`SASRec`，以及**同一个** `brute_force_top_k` 评测函数。数据结构也只有三个字段 `user_idx / item_idx / timestamp`。两边唯一的差别在数据层。

训练预算：

```text
Popularity  无参数
MF          5 轮，batch 1024，lr 0.01，D=64
Two-Tower   9 轮，batch 256，lr 0.01，D=128，temperature=0.1，屏蔽假负样本
SASRec      最多 60 轮，patience=8，batch 256，lr 0.001，D=64，1 层 2 头，max_seq_len=50
```

SASRec 一轮只有 29 个 batch，因为它的训练样本是"每个用户一条序列"，7,176 个用户就是 7,176 条；而两个 ID-only 模型是按交互展开的，KuaiRec 上有 354 万条。这个差异后面会用到。

## 二、先看验证集，再跑一次测试

按项目纪律：验证集只用来确认配置，测试集在锁定之后**只跑一次**。

验证集（`Recall@20`）：Popularity 0.025226、MF 0.029686、Two-Tower 0.023693、SASRec 0.269686。

到这一步其实已经出现一个反常信号：**Two-Tower 比 Popularity 还低**。但我们没有回头调它——配置是预先锁定的，一次训练就用一次，不因为验证集名次不好看而重训。

测试集结果：

| 模型 | Recall@10 | NDCG@10 | Recall@20 | NDCG@20 |
|---|---:|---:|---:|---:|
| Popularity | 0.011010 | 0.004972 | **0.023275** | 0.008060 |
| MF | 0.012404 | 0.005985 | 0.021882 | 0.008333 |
| Two-Tower | 0.012265 | **0.006150** | 0.019233 | 0.007892 |
| SASRec | **0.176585** | **0.101724** | **0.249895** | **0.120139** |

（Recall 与 HitRate 在留一法下相等，只列一个。）

SASRec 这一行要单独看口径：它的标准测试协议把 validation 交互也算进测试历史，而 ID-only 的三个模型只用 train。同一份权重换成只有 train 历史的输入是 0.242369，低 3.0%；MovieLens 上同一组对照低 16.9%。

## 三、为什么不能直接相减：候选空间变了

"Recall@20" 的含义是：在**过滤掉已看物品之后剩下的候选集**里，排序前 20 有没有命中那一条留出目标。所以它的量级取决于候选集有多大。

```text
随机排序的期望 Recall@20 ≈ 20 / 每个用户的候选物品数
```

KuaiRec 过滤后人均候选（中位数）是 **9,103** 个，MovieLens 大约 3,400 个——差 2.7 倍左右。也就是说 KuaiRec 上随机排序的期望值本来就低 2.7 倍。

但除以 2.7 并不能让两个数据集可比。KuaiRec 还有两个性质，都会压低 ID-only 模型的绝对值：

**1. 评测目标更集中。** KuaiRec 的 7,175 个评测用户只落在少数视频上，热门榜和 ID-only 模型能拿到的"对"更少；MovieLens 的目标分散得多。

**2. 正样本更稀。** MovieLens 人均约 94 条训练历史，KuaiRec 人均约 494 条（中位数 451）——历史长了 5 倍多，过滤掉的候选更多，剩下候选里正样本的相对密度也更低。

所以正确读法不是"KuaiRec 的数字乘某个系数就能和 MovieLens 比"，而是：**两个数据集的 Recall 不在同一个尺度上，任何跨数据集的减法或比值都没有意义。** 能比的只有同一数据集内部的排序。

## 四、ID-only 的名次在两个数据集上并不一致

v1 协议下四个模型的排序在两个数据集上是完全一致的。换成 v2 之后，这个结论不成立了：

```text
MovieLens（ID-only）：Popularity 0.083636 < Two-Tower 0.095537 < MF 0.103140
KuaiRec（ID-only）：  Two-Tower 0.019233 < MF 0.021882 < Popularity 0.023275
SASRec（标准协议）：  0.193058 / 0.249895
```

MovieLens 上 MF 最高，KuaiRec 上 Popularity 最高，Two-Tower 两个数据集上都掉到了 ID-only 的末尾。

这件事本身就值得写下来：**这三个模型之间的差距都不大（KuaiRec 上都在 0.02 上下，MovieLens 上在 0.08~0.10），而数据一换，名次就换了。** 把某一次实验的名次当成"双塔比 MF 强"这种规律，是站不住的。

**唯一稳定的是 SASRec。** 两个数据集上它都领先：按 train-only 的统一口径，MovieLens 上是 Two-Tower 的 1.68 倍（0.160331 对 0.095537），KuaiRec 上是 12.6 倍（0.242369 对 0.019233）。一个可能的解释是历史长度：KuaiRec 人均 494 条（中位数 451），MovieLens 人均 94 条。双塔把整个用户压成一个向量，历史再长也只有那么多信息能塞进去；序列模型能吃下最近 50 条，历史越长越连续，它的优势可能越大。但这只是与现有结果一致的假设，不是从这几组实验里直接证出来的因果关系。

## 五、从旧协议里学到的：早停窗口不是中性超参

这一节讲的是早期协议下的一次排查，和上面的 v2 数字无关，但教训通用。

当时 SASRec 用 2 层、`patience=5`，训练到第 2 轮验证指标就到顶，之后一路下降，第 7 轮被早停。看起来像过拟合，但核实后发现：

- 每个 epoch 的监督位置是 **358,545 个**（7,176 条序列 × 最多 50 个位置），不是 7,176 条样本；
- 总参数 789,376 里，item embedding 占 86.9%，真正做序列建模的 transformer blocks 只有 **99,968**。

所以"参数比样本多"这个判断从一开始就不成立。做单变量对照后，dropout 和 weight decay 怎么调都没反应，只有把 `patience` 放到 20、`max_epochs` 放到 80，2 层的验证 Recall@20 才从 0.0839 爬到 0.2549。

**教训是：验证曲线非单调时，`patience` 会改变结论。** 它把"训不上去"和"被停早了"变成同一个现象，而两者的修法完全相反——前者要降容量，后者要加预算。

v2 这次 SASRec 训满 60 轮（best epoch 54），没触发早停，所以没有这个问题。

## 六、这一组结果不能证明什么

写清楚边界比写结果重要：

- **ID-only 三个模型的差距在噪声量级。** 它们都是单 seed 单次运行，名次又在两个数据集间翻转，所以"哪个更好"这类结论没有意义。
- **ID-only 三个模型没有调参。** 它们的超参沿用了 MovieLens 那一档，没有针对 KuaiRec 的规模做搜索。SASRec 那一组做过对照，三个 ID-only 模型没有。
- **SASRec 也没训满。** 60 轮上限，best epoch 54，再多训几轮可能还会涨。
- **冷启动物品没处理。** 43 个物品在训练集里没有交互，它们的 embedding 没有训练信号。这和 MovieLens 的 6 个物品是同一类局限，不是泄漏，但会压低上界。

## 这一篇的坑

- **把 KuaiRec 的 0.019 和 MovieLens 的 0.096 相减。** 候选空间差 2.7 倍，评测目标集中度、历史长度也都不同，跨数据集的差值不携带信息。
- **用"除以候选数"强行对齐两个数据集。** 它只能消掉候选集大小这一项；集中度和历史长度还在，所以对齐之后仍然不能比。
- **把一次实验的名次当规律。** ID-only 三个模型在两个数据集上的名次是翻转的，差距又小，这类结论要多种子才敢下。
- **用"参数量 > 样本量"判断过拟合。** 序列建模的真实参数只有 99,968，监督位置有 358,545；参数总量里的 86.9% 是共享物品表，不参与这个比较。
- **看到验证指标先升后降就认定过拟合。** 先看 `patience` 在第几轮停、那时离峰值多远。
- **在 KuaiRec 上用测试集选轮次。** 三个 ID-only 模型用的是固定轮次（MF 5 轮、Two-Tower 9 轮）；SASRec 的轮次由验证集选出（54 轮）。测试集只跑一次。

## 文献

- **KuaiRec**：Chongming Gao, Shijun Li, Wenqiang Lei, Jiawei Chen, Biao Li, Peng Jiang, Xiangnan He, Jiaxin Mao, Tat-Seng Chua, *KuaiRec: A Fully-observed Dataset and Insights for Evaluating Recommender Systems*, CIKM 2022（[arXiv:2202.10842](https://arxiv.org/abs/2202.10842)）——说明这份数据的全曝光子集与"只记录已发生播放"的大矩阵在评测含义上的区别。
