# 01｜标签先定死：KuaiRec 的 watch_ratio 阈值

> 下面这张表来自标签审计，统计的是"有多少行达标"。真正训练用的是按首次播放判定的版本，所以表里的物品数和实际训练规模会差几十个——那是口径差异，不是数据变了。

最后实际跑下来的结果（`artifacts/kuairec_label_audit.json`）：12,530,806 条原始播放里 4,238,228 条达标；按首次播放判定，得到 **3,557,727** 个正样本对，之后 665,753 次重复播放不再改写标签和时间。映射出 7,176 用户、10,669 物品，严格时间切分为 3,543,377 train / 7,175 validation / 7,175 test。评测时还会把目标时刻之前的未达标播放也过滤掉，避免把实际看过的视频当成"没看过"。

KuaiRec 是短视频交互数据，没有评分，只有 `watch_ratio`（播放时长 / 视频时长）。这一篇解决一件在建模之前就必须做完的事：**把「什么算一次喜欢的交互」写成一条不会随实验改动的规则**，并说清这条规则为什么是它、代价是什么。

## 一、为什么这次不能"先跑起来再说"

MovieLens 的标签是现成的：评分 4 或 5 算正反馈。KuaiRec 没有这个便利，`watch_ratio` 是连续值，卡在哪一格完全由人决定。

麻烦的地方在于，标签不是"数据清洗的一个选项"，它决定了后面所有东西：

```text
阈值 → 正样本集合 → (user, video) 词表 → 用户/物品数 →
      训练集的规模与长尾形状 → checkpoint 的 embedding 表形状
```

词表是模型结构的一部分。阈值一动，`num_users`、`num_items` 就变，之前训好的 checkpoint 全部作废，已经写进文档的指标也全部不可复现。所以顺序只能是：**先用审计把阈值定死、写进配置，再开始训练**。`artifacts/kuairec_data_stats.json` 是这次定案用的审计。

## 二、四个候选阈值放在一起看

审计对 12,530,806 行原始交互（7,176 用户 × 10,728 物品，密度 16.3%）算了四个阈值的完整分布：

| 阈值 | 正样本行 | 占原始行 | 正样本/用户 中位数 | 正样本/物品 中位数 | 有效用户 | 有效物品 |
|---|---:|---:|---:|---:|---:|---:|
| 0.5 | 8,031,791 | 64.1% | 1,056 | 127 | 7,176 | 10,727 |
| 0.8 | 5,683,062 | 45.4% | 732 | 87 | 7,176 | 10,727 |
| **1.0** | **4,238,228** | **33.8%** | **532** | **64** | **7,176** | **10,719** |
| 2.0 | 936,568 | 7.5% | 97 | 14 | 7,175 | 10,611 |

四个阈值都能用，选哪一个不是"哪个指标更好看"的问题，而是"哪个语义站得住"的问题。

## 三、定案：`watch_ratio >= 1.0`

这个值写进项目级配置（`recsys.config.KUAIREC_WATCH_RATIO_THRESHOLD`），所有入口默认读它。

理由按重要性排：

**1. 1.0 是数据自身给出的边界，不是人划的一刀。** `watch_ratio = 播放时长 / 视频时长`，等于 1 就是"看完了整个视频"。0.5 与 0.8 都是"看了一半左右"这种没有物理含义的位置，选它们等于承认边界是随意的。用一条能被解释的线，将来和别人的结果对照时才有共同语言。

**2. 剩下的样本量绰绰有余。** 4,238,228 条正样本行，7,176 个用户每个至少 8 条正样本、中位数 532 条，物品覆盖 10,719 / 10,728。没有任何一个用户或物品因为阈值过高而掉出词表。

**3. 阈值越松，噪声越多。** 0.5 把 64.1% 的播放都记成"喜欢"——短视频的信息流里被划过一半是很常见的行为，这个比例本身就在说它不像正反馈。0.8 是折中，但没有理由。

**4. 阈值越紧，代价开始出现。** 2.0（看了两遍）只剩 936,568 条，4 个用户不足 3 条正样本，117 个验证集目标（来自 88 个不同物品）在训练集里从没出现过。用它换"标签更干净"不划算。

## 四、比阈值更麻烦的两个问题

### 4.1 同一个视频被重复播放

原始 12,530,806 行里只有 10,300,969 个不同的 `(user, video)` 对，1,841,544 对出现过不止一次（重复行占 17.8%）。这 184 万对要分成两种：

- **同一对的时间戳不同**（1,046,078 对）：用户在不同时刻重复播放了同一个视频。
- **同一对只在同一时间戳上重复**（795,466 对）：一次播放被写成了多行，或同一次会话里的重复记录。

这两种都必须处理，否则评测会坏掉：切分是"每个用户按时间取最后两条作为验证/测试"，而评测时会把训练集里出现过的物品从候选里滤掉。如果同一个 `(user, video)` 在训练集里留了一条、又被切分选成了留出目标，那这个目标会在排序前被自己滤掉——**永远不可能命中**，指标被系统性压低，而且错得毫无提示。

早期版本试过把同一对的多条事件合并成一条（时间取最后一次，`watch_ratio` 取最大值）。问题是它会把后来的高观看比例"倒填"到第一次播放上——重复播放确实代表兴趣，但不能把后来的行为算到更早的时间点。所以现在按首次播放判定标签，重复播放不再改变这条样本的正负。

### 4.2 秒级时间戳并列

`big_matrix` 的时间戳到秒。同一用户、同一秒内的多条交互谁先谁后，数据本身判定不了。审计里这个量级：

```text
同一用户同一时间戳出现多次的组   967,717
其中"第一条之外"的行            968,015（占全部行的 7.7%）
```

用 `(timestamp, item_idx)` 在同秒时兜底可以保证可复现，但证明不了真实顺序。所以现在只在 `train < validation < test` 严格成立时才留出目标，同秒边界的用户整个留在 train。

这个限制影响多少留出目标？当前 v2 首次播放标签和严格切分下，7,176 个正反馈用户中 7,175 个符合 `train < validation < test` 边界，因此各有 7,175 个 validation/test 目标；剩余 1 个用户全留在 train。历史四阈值表里的同秒比例是原始行口径，不能直接套到当前首次播放事件。

## 五、阈值定下来之后，评测到底有多难

按首次播放、阈值 1.0 切出来的实际规模：

```text
用户 7,176   物品 10,669
训练集 3,543,377   验证集 7,175   测试集 7,175
```

（同秒边界上的用户整个留在 train，所以验证/测试各少 1 个用户。）

对比 MovieLens 要看清楚口径差异，否则很容易把"两个数据集难度不同"误读成"模型退步了"：

| | MovieLens-1M | KuaiRec |
|---|---:|---:|
| 用户 | 6,038 | 7,176 |
| 物品 | 3,533 | 10,669 |
| 训练交互 | 569,231 | 3,543,377 |
| 评测用户 | 3,025 | 7,175 |
| 评测用户人均训练历史 | 约 94 | 约 494（中位数 451） |
| 留出目标数 | 每个用户 1 条 | 每个用户 1 条 |

KuaiRec 的用户看得多得多（训练历史中位数 451 个视频，占 10,669 个物品的 4.2%），所以过滤掉已看物品之后，每个用户仍有约 9,100 个候选物品（中位数 9,103）。而评测目标只有 1 条——**候选空间更大、正样本更稀**。这条口径差异必须写在结果旁边：两个数据集的 Recall 不能相减。

还有一层是标签本身的边界：66% 的行在阈值 1.0 以下，但"没看完"不等于"不喜欢"——用户可能根本没看到那个视频，或者只扫了一眼封面。big_matrix 里的行是已发生的播放，不是完整的曝光日志，所以"负样本"其实只是"没有被观测为正样本"。`big_matrix` 与 `small_matrix` 不要混用也是同一个理由：`small_matrix` 是接近全曝光的 1,411 人子集（密度 99.6%），把两者拼起来会让"曝光"的含义在同一个文件里发生变化。

## 这一篇的坑

- **把阈值当成可以后面再调的参数。** 它决定词表形状，改一次就要重训全部模型、重写全部指标。
- **保留重复的 `(user, video)` 对。** 留出目标会出现在训练历史里，被排序前的过滤规则滤掉，指标被系统性压低且不报错。
- **用 `small_matrix` 增大训练集。** 它的曝光率接近 100%，和大矩阵的"已播出"语义不同，混用等于让标签规则在数据内部不一致。
- **把"未达标"当成"负反馈"。** 没看完的播放里混着大量"没被看到"，真正能当负样本的只有已观测且明确未看完的部分，这也是本项目用"正样本 + 随机负采样"而不是"正负都来自数据"的原因。
- **直接拿 KuaiRec 的 Recall 和 MovieLens 的比。** 候选空间差 2.7 倍（9,103 对约 3,400），评测目标集中度还差一倍，人均历史差 5 倍以上。
- **以为合并只是"少了几行"。** 它同时改变了留出目标的集合：lab9 里同一份样本、同一条切分规则，原始行切出 788 个目标、其中 66 个混进训练历史；合并后切出 800 个目标、一个都不混。

## 文献

- **KuaiRec**：Chongming Gao, Shijun Li, Wenqiang Lei, Jiawei Chen, Biao Li, Peng Jiang, Xiangnan He, Jiaxin Mao, Tat-Seng Chua, *KuaiRec: A Fully-observed Dataset and Insights for Evaluating Recommender Systems*, CIKM 2022（[arXiv:2202.10842](https://arxiv.org/abs/2202.10842)）——提出这套快手短视频数据集，说明 `watch_ratio` 与"完整播放"的关系，并说明大矩阵里的每一行是一次播放、同一用户对同一视频的重复播放是真实存在的。
- **隐式反馈的负样本边界**：Steffen Rendle, Christoph Freudenthaler, Zeno Gantner, Lars Schmidt-Thieme, *BPR: Bayesian Personalized Ranking from Implicit Feedback*, UAI 2009（[arXiv:1205.2618](https://arxiv.org/abs/1205.2618)）——只把"已观测"的交互当正样本、未观测的当负样本，是目前隐式反馈训练的标准做法，也是这里不把"未达标播放"当负反馈的依据。
- **基线与比较纪律**：Steffen Rendle, Walid Krichene, Li Zhang, John Anderson, *Neural Collaborative Filtering vs. Matrix Factorization Revisited*, RecSys 2020（[arXiv:2005.09683](https://arxiv.org/abs/2005.09683)）——说明"更复杂的模型一定更好"不成立，配置和预算是同等重要的变量；这正是一篇固定在训练之前定标签、固定预算再做对比的理由。
