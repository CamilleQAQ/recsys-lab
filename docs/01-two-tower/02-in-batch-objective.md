# 02｜一个 batch 怎么变成可训练的目标

第 01 篇结束时，模型已经能 forward 了，但输出的还是一堆随机数。这一篇解决：**拿什么当训练目标。**

难点不在于写代码，在于数据里只有正反馈——用户看过什么，从来没人标注"他不喜欢什么"。没有负样本，就没法构造"这个比那个好"的对比。

## 一、一个 batch 天然提供了负样本

### 形状对齐

`DataLoader` 送来的是一个 batch 的正样本对：

```text
user_ids = [u_0, u_1, ..., u_{B-1}]      # [B]
item_ids = [i_0, i_1, ..., i_{B-1}]      # [B]，第 k 项是 u_k 喜欢过的物品
```

两个向量矩阵相乘：

```text
[B, D] @ [D, B]  ->  [B, B]
```

第 `i` 行第 `j` 列是用户 i 对物品 j 的分数。

关键是**输入按正样本对对齐**：用户 i 的正样本恰好落在第 i 列，也就是对角线。于是每一行都是一个 B 选 1 的分类问题，正确答案是列号 i。标签就是 `[0, 1, ..., B-1]`，不需要从数据里读。

### 公式

设归一化后的用户、物品向量为 `ê`，温度为 `T`，batch size 为 `B`：

```text
s_ij = (ê_ui · ê_ij) / T                          分数

L    = -(1/B) · Σ_i log( exp(s_ii) / Σ_j exp(s_ij) )
                          └ 正类 ┘   └ 本行所有候选的和 ┘
```

每一行的分母，是这一行**全部 B 个物品**的指数和。其中 1 个是正类，其余 `B-1` 个是"batch 里碰巧凑到同一行的其他用户的正样本"，被临时当作负类。这就是 **in-batch negatives**。

第 04 篇要修的那处 bug，这个式子看得最清楚：**屏蔽一个候选，就是把它从分母的求和里去掉。** 理解了这一点，"为什么 mask 能修好目标"就不需要额外解释。

### 为什么 target 是列号，不是 item id

`logits` 是 `[B, B]`，它眼里的"类别"是列位置 `0 ~ B-1`，不是电影 ID。把电影 ID 当 target 会直接越界——不过这是个会报错的错误。

真正危险的是它背后的误解：以为在预测"这个 item 是不是正样本"。实际上每行是一个**在给定候选集合内的排序问题**——换一个 batch，同一个用户的正确答案所在列号就变了，标签值本身没有任何固定含义。

## 二、这个目标的收益和代价

**收益**：不需要任何负采样工程。一次 forward 同时得到 B 个正样本和 `B×(B-1)` 个负样本对。

**代价一：负样本数量由 batch size 决定。** 每次更新能看到 `B×(B-1)` 个 in-batch negatives，B 越大负样本越丰富。但 `[B, B]` similarity matrix 的计算和显存开销是 `O(B²)`——这是这套做法的硬边界，也是想再扩大负样本量时得另想办法的原因。

**代价二：一个没有验证过的假设。** 上式默认"非对角位置都是负样本"。可那些物品是从全体正反馈里抽出来的：

> 它们有没有可能，本来就是这一行那个用户在训练集里喜欢过的东西？

这个假设一旦不成立，目标就在自相矛盾：数据说"这是正反馈"，loss 却说"把它当负类压下去"。

**这里先留个问题，第 04 篇会用真实数据把它量出来。** 这是本篇最重要的边界——先把最简单版本跑起来，不猜。

## 三、temperature

### 为什么需要

第 01 篇做过 L2 normalize，cosine 只能落在 `[-1, 1]`。这个范围对 softmax 来说太窄：

```text
scores = [0.42, 0.38, 0.35, 0.40]         →  softmax 最大概率 ≈ 0.26（接近 1/4）
scores / 0.1 = [4.20, 3.80, 3.50, 4.00]   →  softmax 明显更尖
```

一行里最大和最小只差 0.07，softmax 之后几乎是均匀的，模型很难把正类和负类在概率上分开。除以一个小于 1 的数把 logit 的差异放大，softmax 变尖，正类的概率才会明显高于其他候选。

顺带说清楚一点：这里的梯度**不会**因为 softmax 平坦而消失。交叉熵对 logit 的梯度是 `p - y`，概率均匀时它一点都不小。temperature 影响的是**梯度的尺度**——分数先除以 `T`，反向传播时这个 `1/T` 会乘回梯度上，所以 T 越小，同样的 loss 给出的更新步子越大。

### 它在哪里起作用

这里要分清两件事。

**对一个已经训练好的模型，检索阶段改变 T 不改变结果。** 评估和线上检索都只做 Top-K 排序，而所有分数同除一个正数不改变名次——`s_1 > s_2` 与 `s_1/T > s_2/T` 恒等价（`T > 0`）。拿着同一个 checkpoint 换一个 T 去排序，Recall@K、NDCG@K 一模一样。

**但训练时用不同的 T，会学出不同的参数。** 最终指标的差异来自这里，不来自排序那一步。第 03 篇的消融测的就是这件事。

由此有一个实现上的自由度：既然推理侧不依赖 T，**缩放放在 `forward` 里还是 loss 里都行**。本项目统一放在 `forward`，是为了让"模型输出即最终分数"这个接口整齐，检索侧直接拿 `encode_*` 的结果就能用。

### 它是一个要调的超参

不是数学必需。第 03 篇会做它的消融，结论是：在这个数据集上它有用，但不是主要矛盾。

## 四、怎么知道目标写对了

一个能 backward、loss 会下降的目标，**不代表它表达了你想表达的东西**。

判断方法之一：把目标退化到一个已知答案的情形上。这里有一个现成的：

```text
如果每一行的 B 个分数完全相同（模型什么都没学到）
  → softmax 之后每列都是 1/B
  → 每行交叉熵 = -log(1/B) = ln(B)
  → 整个 batch 的 loss 恰好是 ln(B)
```

`B = 4` 时应该是 `ln 4 ≈ 1.3863`；真实训练 `B = 256` 时应该是 `ln 256 ≈ 5.545`。跑之前先把这个数算出来，跑完对不上，说明目标或形状哪里写错了。

这类"退化检查"比"loss 在降"有用得多——它检验的是目标本身，而不是优化器的努力。

还有一个同类的检查：把 mask 全设成 False 时，带 mask 的训练循环必须和不带的**完全等价**，连最终参数都要逐位相同。这是验证"新逻辑没有意外副作用"的标准手法，第 04 篇会用到。

## 五、文献

- **NCE**：Gutmann & Hyvärinen, *Noise-Contrastive Estimation of Unnormalized Statistical Models*, JMLR 2012（[JMLR](https://www.jmlr.org/papers/v13/gutmann12a.html)）——把"从一堆候选里认出正类"变成可训练目标的开创性工作，负采样思路的源头。
- **Sampled softmax**：Jean et al., *On Using Very Large Target Vocabulary for Neural Machine Translation*, ACL 2015（[ACL](https://aclanthology.org/P15-1001/)）——为超大输出空间设计的近似归一化。in-batch negatives 可以看作它的极端省钱版本：不做采样，直接用同批其他样本。
- **BPR**：Rendle et al., *BPR: Bayesian Personalized Ranking from Implicit Feedback*, UAI 2009（[ACM](https://dl.acm.org/doi/10.5555/1795114.1795167)）——只有正反馈时另一条主流路线：不做多分类，而是直接优化"正样本得分高于负样本"的 pairwise 目标。第 04 篇末尾提到的多正样本 loss 属于这一族。
